# Built-in audio on Panther Lake

Built-in audio on Lenovo Yoga Slim 7 Ultra 14IPH11 (83QK, Panther Lake), fixed Jul 20 via linuxPackages_testing; UCM overlay DROPPED Aug 13 (nixpkgs now ships 1.2.16.1), one transition still pending.

**STATUS 2026-07-20 evening: WORKING, verified live on this machine.** Test boot of 7.2.0-rc3 (`linuxPackages_testing`): speakers AND mic AND s2idle all work. Ghost gone, card registered, amps calibrated. Two userspace gotchas found live: (1) UCM 1.2.16 is doubly broken for this card (PlaybackPCM 0 vs 2, AND routes `cs42l43 ASPTX Input` from DP5RX instead of DP6RX), so even applied it would be silent; fixed in 1.2.16.1 (nixpkgs master has it, hash `sha256-zz0cB+CJqDxOziwg8F3WqKq3/NEIdow4gROGiAV1SSs=`; nixos-unstable still 1.2.16 on Jul 20). Stopgap that boot = pro-audio profile + hand-applied UCM EnableSequence via amixer (14 csets, see upstream cs35l56-bridge.conf master). (2) Mic was ONLY `Dmic0 Capture Switch` defaulting off; mics ARE PCH DMICs. My old "mics hang off the SoundWire side" theory was WRONG (an artifact of the wrong rt722 topology). No SDCA mic/jack PCM exists on this board (SmartAmp function only, no headphone jack). NB module gotcha: the fallback's dev_info string lives in `snd-sof-intel-hda-generic.ko`, not hda-common; quirk-name strings compile out, so strings-grep absence proves nothing. History: no soundcard because BIOS dual-sources SDW link 3, advertising a phantom RT722 (`sdw:0:3:025d:0722:01`, UNATTACHED) beside the real cs42l43 (`sdw:0:3:01fa:4243:01`). On 7.0.x the bogus rt722 match entry matched first (SoundWire -61); on 7.1.x no entry matched at all. Amps: 2x CS35L57 on the cs42l43 SPI sidecar, fine all along.

**The upstream fix (in mainline since v7.2-rc1) is NOT the match-table quirk I predicted.** It is soundwire commit `4dab2b904414` "dmi-quirks: Disable ghost Realtek devices" (Keepax): DMI-matches LENOVO + product 83QK and remaps the phantom ADR `0x000330025d072201` to 0 so it vanishes at enumeration. With the ghost gone, NO static ptl-match entry fits, and the hda.c "default SDW machine with function topologies" fallback builds the card from the real cs42l43 + the pre-existing `SND_PCI_QUIRK(0x17aa, 0x3821, ..., SOC_SDW_SIDECAR_AMPS)`. Cirrus refuses new per-machine PTL match entries; function topologies are the strategy now.

**THE tracker is thesofproject/linux issue #5786** (exact machine, 62 comments; my old note "no upstream issue exists" became wrong on 2026-05-25). #5759 (ASUS) closed completed 2026-07-20. Confirmed working on 83QK: clean v7.2-rc1 (wangzy85222, Jul 9) and 7.2.0-rc3 (Arch thread id=313255, Jul 20). Stable backports uncertain; Keepax maintains curated backport branches (charleskeepax/linux `v7.0-cs42l43`, 10 patches, and `v6.18-cs42l43`).

**Verified locally on the installed pinned 7.0.13 (2026-07-20):** function-topology fallback IS present (string lives in `snd-sof-intel-hda-generic.ko`, NOT hda-common — a strings-grep of the wrong module misled twice); 17aa:3821 sidecar quirk at v7.0 `sof_sdw.c:849` (quirk name strings compile out without SND_DEBUG_VERBOSE, so absence in strings proves nothing); CONFIG_SND_SOC_SDCA* all =m; sof-firmware 2025.12.2 ships the needed `sof-sdca-{jack-id0,1..4amp-id2,mic-id4}.tplg`; cirrus `cs35l57-b2-dsp1-misc-17aa3821-spkid{0,1}-amp{l,r}.bin` + wmfw symlinks → `CS35L56_Rev4.5.3` all present. So 7.0.13 needs ONLY the ghost quirk + 3 small fixups.

**Recipe A (daily driver, keeps 7.0.13 + working suspend):** `boot.kernelPatches` with latin-1's 8-patch set (the #5786 reporter's own Fedora set, base = kernel-7.0.13, my workflow agent apply-tested all 8 against vanilla 7.0.13: zero fuzz):
`https://raw.githubusercontent.com/latin-1/os-packages/e2fb1eb4804095f542f1f02dfb077ba22084d9cf/kernel/f44/patches/000{1..8}-*.patch` (0003 = the ghost quirk; 0004 adds the is_amp field that 0006/0007 need; 0008 dai-type append, without it card comes up dmic-only). Triggers one local kernel build. Do NOT use latin-1's current 4-patch main set (base 7.1.3, patch 0003 fails on 7.0.13).
**Recipe B (zero-build validation):** `boot.kernelPackages = pkgs.linuxPackages_testing` = 7.2-rc3 on the Jul-2026 nixpkgs pin, binary-cached; also retests the [Kernel 7.1.0 s2idle suspend hang](kernel-7.1.0-s2idle-suspend-hang.md) on 7.2.

**Both recipes also need alsa-ucm-conf ≥ 1.2.16.1** (nixpkgs had 1.2.16 as of Jul 20): the cs35l56-bridge.conf fix (PR #778) changes PlaybackPCM `hw:${CardId},0` → `,2` and drops a bogus ConflictingDevice; without it speaker routing/volume is wrong once the card exists. Overlay `overrideAttrs` version bump, or wait for nixpkgs. Verify: `grep PlaybackPCM .../ucm2/sof-soundwire/cs35l56-bridge.conf`.

**2026-08-13 POST-REBOOT RESULT: PASSED on 7.2.0-rc7 with stock UCM.** Card `sof-soundwire` on **HiFi**; sinks `HiFi__Speaker__sink` + `HiFi__HDMI{1,2,3}__sink` under unchanged names; built-in mic present.

**Name correction for future checks: the built-in mic source is `alsa_input.pci-0000_00_1f.3-platform-sof_sdw.HiFi__Mic__source`** (description "Core Ultra Processors (Series 3) HD Audio Digital Microphone", 4ch s32le). It is NOT called "dmic" in pactl. Grepping sources for `dmic` returns nothing and looks like a failure when the mic is fine. Grep for `HiFi__Mic` or just list all sources. Also note the built-in mic is usually NOT the default source when the LG UltraFine is connected (its USB mic wins); that is normal, not a fault. Nothing in the repo hardcodes device names (niri uses `@DEFAULT_AUDIO_SINK@`/`@DEFAULT_AUDIO_SOURCE@`, and the Mod+Mute cycler builds names from pactl JSON at runtime), so UCM renames cannot break the bindings.

**2026-08-13: UCM overlay DROPPED.** nixos-unstable now ships stock `alsa-ucm-conf` **1.2.16.1**, verified to contain the actual fix (`PlaybackPCM "hw:${CardId},2"` in `ucm2/sof-soundwire/cs35l56-bridge.conf`), not just a matching version string. Removed all three pieces: the `ALSA_CONFIG_UCM2` sessionVariable, the wireplumber `asDropin` env, and the `alsa-ucm-conf-latest` overlay attr. ALSA now uses the default lookup path. Applied together with the 7.2-rc6 → rc7 kernel bump, so **the post-reboot sink check below covers both at once**; if audio is wrong after that reboot, the two candidate causes are the stock UCM and rc7.

**Still pending (the other transition):** `linuxPackages_latest` was 7.1.8 on 2026-08-13, so the switch off `linuxPackages_testing` is not yet possible. Comment in configuration.nix still marks it.

**CHECK REQUESTED BY RAJ — at the linuxPackages_latest switch (7.2 stable) and again when dropping the UCM overlay:** kernel-side ALSA changes and the pinned UCM 1.2.16.1 interact exactly at these transitions (UCM profiles match on kernel-exposed component names). Immediately after each switch verify the built-in card survived: `pactl list cards | grep -iE 'card_name|Active Profile'` must show sof-soundwire on **HiFi** (not a fallback profile), and `pactl list short sinks` must list Speaker + HDMI1/2/3 under **unchanged names** (the Mod+Mute cycle script matches on these), plus the built-in mic as `HiFi__Mic__source` (grep `-i mic`, NOT `dmic`, see the name correction above). Symptoms of a clash: missing/renamed built-in sinks, card stuck in pro-audio/fallback profile, mic gone.
