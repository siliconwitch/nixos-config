# 13 August 2026: agent benchmarks killed the compositor

Aug 13 2026 'unstable system' incident fully diagnosed: Claude Code subagents (cyberdeck session) ran compositor benchmark scripts on the live machine that pkill'd niri twice; greetd died permanently (no Restart=); NOT the rc7 kernel, NOT the GPU, NOT the update. Lessons about agent-run scripts.

On 2026-08-13 Raj reported "the updated system seems really unstable" (desktop crashed repeatedly, then total loss incl. tty2, hard power-off). A 6-angle forensic workflow proved the update and hardware innocent. Root cause: Raj's **cyberdeck** Claude Code session (project `/home/raj/projects/cyberdeck`, session 4ac023dc, workflow wf_458a83ab-3d7, ~15 subagents) was researching Wayland compositors and its subagents wrote and ran `bench.sh`/`bench2.sh`/`bench3.sh` (10:50:05-10:50:53) in the session scratchpad. The scripts launched EVERY compositor (`cage dwl mango river sway labwc niri hyprland wayfire`) by store path on the LIVE machine, then cleaned up with `pkill -f "$name"` (bench.sh) and `kill -9 -- -$(pgid of pgrep -n -x "$name")` (bench2.sh). The `niri` iterations matched the SESSION compositor:

- 10:51:17 SIGTERM killed niri #1 (bench.sh `pkill -f niri`). greetd restarted the session ("restarted a couple of times").
- 10:52:06 SIGKILL killed niri #2 (bench2.sh; its own benched niri had already died so `pgrep -n -x niri` resolved to the session one). greetd: "check_children: greeter exited without creating a session" then Deactivated. NixOS greetd unit has **no Restart=** and **Conflicts=getty@tty1.service**, so no graphical login AND blank tty1 forever = "totally went down".
- The two Hyprland 0.56.2 SIGABRTs (10:51:19, 10:52:08) were the benchmarks launching hyprland into a dying session: `CBackend::create() failed!` (no DRM master, no Wayland socket). Symptom, not cause. First-ever Hyprland run on the machine; it autogenerated the stray `~/.config/hypr/hyprland.lua` (crash debris, deletable). Hyprland is on disk only because programs.hyprlock -> hypridle unit PATH.
- tty2 WORKED: Raj authenticated twice (10:52:40, 10:53:02) but user@1000.service was wedged mid-stop (the foot-server scope `app-niri-sh-2153.scope` never reported Stopped), so logins hit "Requested transaction contradicts existing jobs ... systemd-exit.service" and gave no usable shell.
- 109 "Power key pressed short" events 10:53:15-19 were journalled (kernel alive to the last line, NO freeze/panic) but ignored: logind.conf HandlePowerKey=ignore. Hard power-off followed; next boot showed fsck journal recovery + ESP dirty bit + one unread ACPI BERT record.
- Kernel/GPU fully exonerated across rc5/rc6/rc7 boots: zero xe/drm/GuC errors ever. The screen LOOKING dead was niri vs the docked 5K + lid close: 100x Smithay "Atomic Test failed for new properties on crtc" retry storm (known class: niri #3719 lid-close freeze with mode-change workaround, #869 phantom dock connector, cosmic-comp #2688 unbounded retry). rc7 was only exercised 22 min WITH the dock, so keep half an eye on redock behaviour.

**Why:** Raj must be able to trust that agent sessions won't take down his machine, and future me must not repeat this.

**How to apply:**
- NEVER launch compositors/display servers, and NEVER `pkill`/`killall` by generic process name, on Raj's live machine; those names (`niri`, `foot`, etc.) match his session. Benchmarks belong in a headless VM or a nested/headless backend, or don't run at all.
- A rejected tool call does not undo prior `nohup ... &` (bench3 was rejected at 10:51:17 but already detached); the two earlier scripts also outlived their "Exit code 144" tool results and kept running after the session died. Treat backgrounding of destructive scripts as itself destructive.
- If the desktop dies again while greetd shows nothing and tty1 is blank: tty2 login may authenticate but be useless if user@1000 is wedged; `systemctl restart greetd` from a root shell would be the recovery, and power key is configured ignored (hold for EC off).
- The Aug 10/13 updates changed only: rc5->rc6->rc7 kernel, mesa 26.1.6->26.2.0, xwayland-satellite 0.8.1->0.8.2, hyprland 0.56.1->0.56.2 (unused). See [Session recovery gaps in greetd and the power key](session-recovery-gaps-greetd-powerkey.md) and [dhcpcd boot segfault, use-after-free](dhcpcd-boot-segfault-uaf.md) for the two real defects found alongside; morning "foot crash" was actually the [LG UltraFine 5K over Thunderbolt](lg-ultrafine-5k-thunderbolt.md) EDID failure.
