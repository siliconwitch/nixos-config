# Audio sink cycling and phantom HDMI sinks

Mod+Mute sink cycling — WirePlumber silently refuses set-default-sink onto jack-down sinks (old script got stuck); HDMI1/2/3 sinks are dynamic iGPU slots, keep all 3 for the projector; never pactl move-sink-input (pins apps).

Facts established 2026-07-21 while fixing the "Mod+Mute does nothing" report (all verified live + against WirePlumber 0.5 docs/source):

- **WirePlumber silently reverts `pactl set-default-sink` onto a sink whose active port is `not available`.** The old niri cycle script always tried "next in list" = jack-down `HiFi__HDMI1__sink`, so the default never moved: hotkey looked dead while manual mixer switching worked. Rewrote the `Mod+XF86AudioMute` binding in niri/config.kdl to filter by port availability (`pactl -f json` + jq: drop sinks whose active_port availability is "not available"; sinks with no ports, e.g. RAOP, count as available).
- **HDMI1/2/3 sinks = the iGPU's 3 display-audio converter slots**, present regardless of what's plugged. Connector→PCM assignment is DYNAMIC at hotplug (so "disable 2, keep 1 for the projector" is unreliable — all or none). **KEEP all 3**: Raj's home projector (USB-C→HDMI dongle) uses one of them; his UltraFine monitor never does (USB audio only, see [LG UltraFine 5K over Thunderbolt](lg-ultrafine-5k-thunderbolt.md)). WirePlumber 0.5 has NO hide-while-unplugged option; the disable recipe if ever wanted: `services.pipewire.wireplumber.extraConfig."51-x"."monitor.alsa.rules"` match `node.name` → `update-props."node.disabled" = true` (full removal from all mixers).
- **Never script `pactl move-sink-input`:** streams follow the default automatically (`linking.follow-default-target`, default true); an explicit move persistently pins that app via `~/.local/state/wireplumber/stream-properties` (NOT `restore-stream` in WirePlumber 0.5) and it stops following future default changes. The old script's move loop had pinned Chromium to the dead HDMI1 sink — cleaned Jul 21 (stop wireplumber → sed the `"target"` key out → start; editing while running gets overwritten).
- That state file also holds harmless leftovers (old pro-audio profile entries, MacBook raop, DDJ-400): volume memories only, don't clean.
