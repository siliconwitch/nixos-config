# LG UltraFine 5K over Thunderbolt

LG UltraFine 5K monitor — speakers/mic/camera are USB behind Thunderbolt auth (bolt), NO DP audio path; 4K-only on niri (tiled 5K unsupported); phantom 2nd-tile output auto-disabled by ultrafine-tile-off watcher; brightness via USB HID not ddcutil (working hidraw recipe in file, scale 0-54000); corrupt-EDID-at-connect → 640x480, fix = monitor power-cycle NOT cable replug.

Raj's external display is an **LG UltraFine 5K (27MD5KL-class)** on Thunderbolt (TB device `0-1`, uuid `c6030000-0062-641e-03e6-2dd6e2b27108`, gen 3).

**Audio/mic/camera are ALL USB devices behind the TB USB tunnel; there is NO DisplayPort audio path on this monitor** (designed for Macs, USB audio only — confirmed by research Jul 21 2026). The HDMI1/2/3 PipeWire sinks are therefore never this monitor (see [Audio sink cycling and phantom HDMI sinks](audio-sink-cycling-phantom-hdmi.md)).

**Fix applied AND VERIFIED 2026-07-21:** monitor was `authorized=0` (domain security `user`, nothing authorized TB devices) → video worked (DP tunnels need no auth) but USB hub/speakers/mic/camera never enumerated. Added `services.hardware.bolt.enable = true` to configuration.nix; after switch, boltd auto-enrolled the already-connected monitor on its own first activation (policy `iommu`, stored — survives reboots/replugs; both TB domains have `iommu_dma_protection=1`). Confirmed enumerated: LG hubs, "LG UltraFine Display Audio" (PipeWire sink `alsa_output.usb-LG_Electronics_Inc._LG_UltraFine_Display_Audio-00.analog-stereo` + a Mono mic source), "LG UltraFine Display Controls" (HID, for brightness), "LG UltraFine Display Camera" (V4L2). WirePlumber initially made the LG mic the default source.

**4K not 5K is expected on niri:** 5120x2880@60 is a tiled dual-DP-stream mode (two 2560x2880 halves — the mysterious disabled second DP output is the other tile); niri lacks DRM TILE stitching (open niri issue #1921, filed for exactly this monitor; still open Aug 3 2026). Single-stream fallback = 3840x2160, which is what runs. Even compositors that stitch show a mid-screen tearing seam.

**Phantom second tile (diagnosed + fixed Aug 3 2026):** some mornings the display wakes announcing BOTH tiles; niri logs "new connector DP-2 duplicates make/model/serial of existing connector DP-1, unnaming" and enables the tile as a phantom 2048x2304 monitor the mouse falls into (user first blamed lid handling; eDP-1 was fine). Constraints verified in niri 26.04 source: unnamed outputs have make/model/serial = None and `OutputName::matches()` has an explicit guard returning false for name-string matches, so `output "Unknown Unknown Unknown" { off }` in config.kdl can NEVER match; only connector matching works, and connector names float (projector "PNP(FMX) Laser Proj" enumerated as DP-1 on Aug 2, LG main tile as DP-1 on Aug 3). Maintainer punts duplicate handling to external scripts (niri discussion #2327). Fix: `systemd.user.services.ultrafine-tile-off` in configuration.nix — follows `niri msg --json event-stream`, on every WorkspacesChanged (fires on output connect; niri-ipc 26.4 has NO outputs event) turns off any enabled output with make=="Unknown" && model=="Unknown" while an LG UltraFine is connected. IPC JSON: unnamed tile shows make/model "Unknown", serial null, current_mode null when disabled. Imperative `niri msg output DP-2 off` does not survive re-enumeration (that was the Jul 21 non-fix).

**Corrupt EDID at connect → stuck at 640x480 (diagnosed + fixed Aug 4 2026):** on a morning connect the display served an EDID whose block-0 checksum failed (`EDID block 0 (tag 0x00) checksum is invalid` in dmesg), so DRM fell back to VESA safe modes and niri drove the 5K at 640x480 ("preferred") / logical 426x320. Key facts: (1) **TB cable replug does NOT fix it** — same corrupt read on reconnect; (2) a later kernel retry can cache a VALID EDID in `/sys/class/drm/card0-DP-1/edid` (checksums verifiable by summing each 128-byte block mod 256; valid blob advertises the 3840x2160 DTD) while the connector's mode list stays stale with fallback modes; (3) **fix = power-cycle the monitor itself** (pull its power cord ~10 s — no power button) to force a fresh handshake; verified instant recovery to 3840x2160@60. Fallback if cached EDID is valid but modes are stale: `echo detect | sudo tee /sys/class/drm/card0-DP-1/status` forces a re-probe without touching cables (untested — power cycle worked first). The phantom-tile watcher is unrelated to this failure and behaved correctly throughout.

**Corrupt-EDID recurrence, Aug 13 2026 (misreported as "foot server crashed"):** on morning resume 08:24:43 the same invalid-EDID-block-0 failure hit (DP-1 to 640x480, duplicate connector failed with "No space left on device"). Raj read the wrecked terminals as a foot crash and rebooted at 08:26:52; forensics proved foot never died (no coredump ever, same PID throughout, clean `reboot`). If he reports terminal/app "crashes" right after a morning resume with the 5K docked, check `journalctl -k | grep -i edid` FIRST. Related niri upstream (all unfixed, found Aug 13): #3719 lid-close/output-off freeze with "missing surface in vblank callback", recovery = force a mode change or restart session; #869 phantom dock connector spamming Smithay "Atomic Test failed for new properties on crtc" (the retry loop has no backoff, cosmic-comp #2688); #3226 connector identity degrading to Unknown after hotplug/TTY switch. NB niri 26.04 (already running) ALREADY contains the dock fixes that exist (#1722 stale-outputs-on-dock-disconnect, plus "docks that cause monitor EDID to be loaded late"), and this failure still recurred on 26.04, so don't expect a niri upgrade alone to cure it.

**Brightness (WORKING method, verified Aug 4 2026):** DDC/CI does NOT work (no i2c over the tunnel; ddcutil never sees it — Raj still assumes "i2c lines", correct him gently). Working path: HID feature report on the "LG UltraFine Display Controls" USB device (043e:9a70), which exposes THREE hidraw interfaces — the right one has a **68-byte report_descriptor** (Monitor usage page 0x82, usage 0x10 Brightness; siblings are 33-byte vendor and 234-byte sensor-hub). Report 0 layout: `[0x00 report-id][u32 LE brightness][u16 second field, zeros fine]`, raw scale **0–54000** (descriptor's LogMax 540 is unit-exponent-scaled and misleading). Set via `HIDIOCSFEATURE` ioctl; hidraw is root-only (no udev rule yet), Raj runs it with sudo. **Gotchas:** (1) NEVER write 540 thinking it's max — it's near-minimum, screen goes almost black; (2) GET-feature readback parsed wrong on this device (a verify-then-fallback loop misjudged the set and dimmed the screen); blind SET works, keep it simple. Working script (hidraw index floats, match by VID:PID + 68-byte descriptor):

```python
import fcntl, glob, os, sys
for p in glob.glob("/sys/class/hidraw/hidraw*"):
    if "0000043E:00009A70" in open(p + "/device/uevent").read() \
            and len(open(p + "/device/report_descriptor", "rb").read()) == 68:
        dev = "/dev/" + os.path.basename(p); break
else: sys.exit("display controls device not found")
buf = bytes([0]) + (54000).to_bytes(4, "little") + b"\x00\x00"
fd = os.open(dev, os.O_RDWR)
fcntl.ioctl(fd, (3 << 30) | (len(buf) << 16) | (ord("H") << 8) | 0x06, buf)
os.close(fd)
```
