# Nix dev shells across ~/projects

~/projects dev setup: docs & superstack use committed flake devShells + direnv; s2-firmware (nRF/Zephyr) uses system nix-ld + documented config, NOT a flake. All working 2026-06-04.

Raj's dev projects live in `~/projects` (superstack = Go, s2-firmware = Zephyr/nRF, docs = Jekyll/Ruby are the main three). On this NixOS box each project gets a committed `flake.nix` devShell + `.envrc` (`use flake`), auto-activated by direnv (`programs.direnv.enable = true` in configuration.nix — that one line adds the zsh hook and nix-direnv). This replaces the brew/apk/go-install steps in the Mac-oriented READMEs.

Set up & verified 2026-06-04:
- **docs**: `ruby_3_3` (only 3.3/3.4 in nixpkgs); native gems (nokogiri) compile from source with gcc/gnumake/pkg-config/zlib/libffi + `BUNDLE_FORCE_RUBY_PLATFORM=1`; gems vendored to `.bundle`. Promoted `webrick` out of the Windows-only `platforms` block to top-level in the Gemfile (Ruby 3 dropped it from stdlib; `jekyll serve` needs it). Don't add a separate `pkgs.bundler` — `ruby_3_3` ships its own and the standalone one is built for 3.4.
- **superstack**: go, air, templ (from nixpkgs, not `go install`), postgresql_17, screen, stripe-cli, ngrok, python3+numpy. nixpkgs imported with `config.allowUnfree=true` (ngrok is unfree). `PYTHON_PATH` is set to the Nix python env's bin so the agent's numpy sandbox works without a virtualenv. One-time README steps (`.env` secrets, initdb/schema/seed, cert-gen) still apply but run inside the shell.

**s2-firmware** (resolved via nix-ld, deliberately NOT a flake): the nRF Connect SDK toolchain `nrfutil sdk-manager install v3.0.1` downloads is prebuilt Linux blobs stock NixOS can't run. Fix is `programs.nix-ld.enable = true` + `programs.nix-ld.libraries = [ stdenv.cc.cc zlib libidn2 libunistring gnutls gmp libkrb5 libxcrypt-legacy e2fsprogs ]`. The gnutls…e2fsprogs ones are needed by the toolchain's bundled `git-remote-https` for `west update` (HTTPS fetch) — `libcrypt.so.1` comes from `libxcrypt-legacy`, not `libxcrypt`. Verified by overriding `NIX_LD_LIBRARY_PATH` at runtime (an env value overrides the system `libraries`), not by ldd (ldd over-reports). Host tools `gnumake`, `nrfutil`, `segger-jlink` are in systemPackages; segger-jlink needs udev + allowUnfree + permittedInsecurePackages "segger-jlink-qt4-874".

Kept in configuration.nix + documented in the firmware README (not a per-project flake) because the env is irreducibly system-level (nix-ld loader at /lib64, udev rules) + external (the ~4 GB SDK in `~/ncs` on Linux, `/opt/nordic/ncs` on Mac) — a flake buys no clean portability. Makefile + README are de-hardcoded: `nrfutil sdk-manager toolchain launch --ncs-version v3.0.1 -- west …` runs west in the toolchain env (no per-install hash; was `7cbc0036f4` here, not the README's stale `ef4fc6722e`). `ZEPHYR_BASE` and the SDK `cd` dir are derived from `toolchain env`'s PATH by stripping `/toolchains/<hash>`.
